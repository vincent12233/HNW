# 可观测性与告警

## 接入方式

- Prometheus 抓取 API 的标准入口 `GET /metrics`；`GET /health/metrics` 保留兼容，建议生产环境每 15 秒抓取一次。
- Prometheus 配置位于 `docker/observability/prometheus.yml`，Grafana 面板位于 `docker/observability/hnw-api-dashboard.json`。
- 本地联调先启动 `compose.local-test.yaml`，再设置 `HNW_GRAFANA_ADMIN_PASSWORD` 并启动 `docker compose -f compose.observability.yaml up -d`。生产环境必须改用受控凭据、持久化存储和告警接收器。
- 告警规则位于 `docker/observability/alerts.yml`，由生产 Prometheus 的 `rule_files` 加载。
- 告警接收平台、真实联系人和升级电话属于部署环境配置，不写入仓库。
- `owner` 标签定义默认责任团队；上线前必须映射到实际值班组。

## 指标范围

- HTTP：请求量、4xx/5xx、平均响应时间。
- 关键业务拒绝：登录、刷新令牌、下单、提现、KYC 和限流。
- 行情：流连接、报价接收、报价入库失败、WebSocket 连接和广播。
- 资金：提现请求、批准和拒绝；关键业务成功/失败按低基数事件名统计。
- 基础设施：Redis 限流存储连接状态及异常。
- KYC：病毒扫描尝试、跳过、通过、拒绝、不可用及累计耗时。
- 外部依赖：Google、Yahoo、NSE、BSE、RSS 与 GDELT 的尝试、成功、失败和累计耗时。

## 错误采集接入

- Flutter 与 Admin 将脱敏报告发送到 `POST /observability/client-errors`；发送失败不阻塞用户操作。
- API 对入站字段执行类型、长度和事件白名单校验，并再次脱敏后写入结构化日志。
- 配置 `ERROR_REPORT_WEBHOOK_URL` 可将二次脱敏报告转发到正式平台；生产 URL 必须为 HTTPS。
- `ERROR_REPORT_WEBHOOK_TOKEN` 仅由 API 服务端使用，禁止放入 Flutter、Admin 或 `NEXT_PUBLIC_*` 环境变量。
- 转发有 3 秒超时且失败降级为本地日志与指标，不得递归上报。

## 隐私与错误报告

- API 错误报告统一生成错误指纹，便于聚合同类问题，不使用用户身份作为指纹输入。
- 日志自动脱敏 Bearer 凭据、JWT、令牌、密码、密钥、邮箱、电话号码、用户主目录和大段编码数据。
- HTTP 审计日志不记录原始 IP、User-Agent、请求体、Authorization、Cookie 或上传内容。
- 只有 5xx 错误保留脱敏后的堆栈；4xx 仅保留错误类型、状态和请求编号。
- Flutter、Admin 和 API 均提供脱敏报告对象及可替换上报接口。
- 接入第三方错误平台时只能转发脱敏报告对象，不得直接转发原始异常、请求或用户对象。
## API 5xx 告警

1. 检查 `/health/ready`、数据库连接和最近部署版本。
2. 按 `requestId` 关联结构化日志，不得复制令牌、密码或 KYC 内容。
3. 若 5xx 比例持续超过 5%，停止继续发布并回滚最近变更。
4. 恢复后记录开始时间、影响接口、根因、修复和预防措施。

## Redis 限流存储告警

1. 检查 Redis 健康、网络和 `RATE_LIMIT_REDIS_URL`。
2. 确认 API 是否进入内存限流或启动失败状态。
3. 不要通过关闭限流来消除告警；优先恢复 Redis 或隔离故障节点。

## 外部供应商告警

1. 使用指标事件名识别供应商与操作，例如 `external_yahoo_quote_failed`。
2. 检查供应商状态、凭据、配额、DNS、TLS 与请求超时。
3. 行情供应商故障时停止展示陈旧价格为实时价格，并启用明确降级提示。
4. Google 验证故障时保留密码登录，不得绕过令牌校验。

## KYC 扫描告警

1. 扫描器不可用时保持失败关闭，禁止未扫描文件进入审核流程。
2. 恶意文件拒绝告警只包含提交编号和时间，不包含文件、证件号或个人信息。
3. 合规值班人员确认事件后，按安全事件流程保留最少必要证据。

## 行情与 WebSocket 告警

1. 检查商业行情供应商连接、订阅数量和报价更新时间。
2. 区分供应商断流、报价解析失败、数据库入库失败和 WebSocket 广播失败。
3. 无法确认实时性时向客户端显示延迟或不可用状态，不得静默沿用旧报价。

## 关键业务告警

1. 下单、提现或 KYC 拒绝在窗口内达到阈值时，先区分用户输入拒绝、权限/合规拒绝与服务端故障。
2. 比较 `hnw_business_events_total` 与 `hnw_business_failures_total`，判断失败比例及影响持续时间。
3. 不得通过降低风控、资金或 KYC 校验来消除告警；必要时暂停入口并保留已提交记录。
4. 使用 request ID 定位日志，不在告警标签中加入用户、订单、证件或账户标识。
