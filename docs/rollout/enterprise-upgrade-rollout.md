# 企业级升级渐进发布方案

## 发布前门禁

仅从通过全部 CI 的同一 Git SHA 构建不可变镜像。完成备份恢复演练、容量/故障报告、安全扫描、数据库向前兼容检查及零差异对账。确认负责人、观察窗口和一键应用回滚路径。

注册、登录、忘记密码、人工存款、交易核心流程及交易请求契约属于受保护流程；任何变化或失败都必须停止发布。

## 渐进阶段

1. 内部环境：员工合成账户，覆盖 Web/PWA、Android、所有后台角色和完整二级页面。
2. 小比例队列：仅已批准的极小流量，至少观察一个业务高峰；比较错误率、p95/p99、订单结果、行情陈旧和对账。
3. 逐级扩大：每一级均需固定观察窗口及人工批准，不因“暂时正常”跳级。
4. 全量：继续增强观察至少一个完整市场交易时段，并保留旧镜像。

## 自动停止条件

出现以下任一情况立即停止扩大并隔离影响：受保护流程回归；财务对账非零；重复订单/流水；未知订单状态增加；行情陈旧未提示；5xx/SLO 超阈值；Redis 失败关闭异常；权限、审计或敏感数据泄露。

## 每阶段证据

记录 SHA、镜像摘要、配置版本、开始/结束时间、流量比例、指标截图、合成交易结果、零差异对账、异常和批准人。客户标识不得进入发布记录。
