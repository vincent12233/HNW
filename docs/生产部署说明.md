# 生产部署说明

面向**正式服务器**部署（Node 进程 + PostgreSQL + Nginx）。仓库的 `compose.local-test.yaml` 仅用于隔离的本机联调，包含开发服务器及测试账号配置，不是生产部署配置。无 Docker 的本机联调见 `docs/本地启动与联调.md`。

正式环境至少需要：一台后端服务器、一个 PostgreSQL 数据库、五个可访问的后台域名、客户 App 的正式 API 地址，以及 HTTPS。

## 推荐域名

| 用途 | 示例 |
| --- | --- |
| API 后端 | `https://api.example.com` |
| 超级管理员后台 | `https://admin.example.com` |
| 管理员后台 | `https://manager.example.com` |
| 财务后台 | `https://finance.example.com` |
| 业务员后台 | `https://business.example.com` |
| 专用运营员后台 | `https://operator.example.com` |
| 客户 Web App，可选 | `https://app.example.com` |

如果只发布 Android App，客户 Web App 域名可以不配置。

## 服务器环境

推荐准备：

- Node.js **24**（与 CI 一致；最低 **20.19+** / **22.12+**，勿用 21.x）
- npm
- PostgreSQL **17.x**（推荐 17.11；最低 15+）
- Flutter SDK **3.47.4**（stable，与 CI 一致），用于客户 App 打包
- Java JDK，用于 Android APK/AAB 打包
- Nginx 或同类反向代理
- HTTPS 证书
- 进程守护（systemd、PM2 或同等工具），保证重启后自动拉起 API / 五个后台

## 部署顺序（建议）

1. 准备 Postgres，只允许服务器内网访问；配置自动备份
2. 部署 API：环境变量 → `npm ci` → `db:generate` → `db:migrate` → `seed` → `build` → `start:prod`
3. 确认 `https://api.example.com/health` 正常
4. 分别为五个 `NEXT_PUBLIC_BACKEND_ROLE` 构建并启动 admin
5. 配置 Nginx / HTTPS 反代到本机端口
6. 打包客户 App（`API_BASE_URL=https://api.example.com`）
7. 修改所有种子后台账号默认密码

## API 后端

进入 API 目录：

```bash
cd apps/api
cp .env.example .env
```

修改 `.env`（生产至少改这些）：

```env
NODE_ENV=production
DATABASE_URL="postgresql://正式数据库用户:正式数据库密码@数据库地址:5432/正式数据库名?schema=public"
RATE_LIMIT_REDIS_URL="redis://正式Redis地址:6379"
JWT_SECRET="换成≥32位高强度随机密钥"
TWO_FACTOR_ENCRYPTION_KEY="换成独立≥32位高强度随机密钥"
OTC_KEY_ENCRYPTION_SECRET="换成另一组≥32位高强度随机密钥"
OBJECT_SIGNING_SECRET="换成第三组≥32位高强度随机密钥"
ADMIN_FIXED_INVITE_CODE="换成≥12位强唯一邀请码"
ADMIN_INITIAL_PASSWORD="≥12位且五角色互不相同"
FINANCE_INITIAL_PASSWORD="≥12位且五角色互不相同"
SUPPORT_INITIAL_PASSWORD="≥12位且五角色互不相同"
BUSINESS_INITIAL_PASSWORD="≥12位且五角色互不相同"
MANAGER_INITIAL_PASSWORD="≥12位且五角色互不相同"
CORS_ORIGINS="https://admin.example.com,https://manager.example.com,https://finance.example.com,https://business.example.com,https://operator.example.com,https://app.example.com"
VIRUS_SCAN_URL="https://malware-scanner.example.com/scan"
VIRUS_SCAN_BEARER_TOKEN="可选扫描端 Bearer Token"
PRIVATE_OBJECT_ROOT="/var/lib/hnw/private-objects"
HOST=0.0.0.0
PORT=3000
```

`SHADOW_DATABASE_URL` 仅在本机 `prisma migrate dev` 需要；服务器 `npm run db:migrate`（`migrate deploy`）不依赖影子库。

生产环境必须提供独立 Redis，并设置 `RATE_LIMIT_REDIS_URL`。API 使用 Redis 在所有实例间共享限流计数；Redis 不可用时受保护请求返回 503，避免绕过登录、资金和交易接口的限流。

将 `PRIVATE_OBJECT_ROOT` 设为**绝对路径**并挂到持久加密磁盘（KYC 证件等私有文件）。相对路径在生产环境会拒绝启动。`VIRUS_SCAN_URL` / `CORS_ORIGINS` 必须为公网 HTTPS（拒绝 localhost / 内网地址）；生产缺失扫描端时 KYC 上传会直接失败。

病毒扫描约定：API 对扫描端点发送 `POST`，`Content-Type: application/octet-stream`，请求体为文件字节；若配置了 `VIRUS_SCAN_BEARER_TOKEN` 则附带 `Authorization: Bearer …`。扫描端需在响应正文返回 `CLEAN`（大小写不敏感）。非 `CLEAN` 或不可达时，生产上传失败关闭。本机可临时用 `node scripts/virus-scan-stub.mjs`（仅监听 127.0.0.1，勿对公网暴露）。

安装、迁移、构建并启动：

```bash
npm ci
npm run db:generate
npm run db:migrate
npm run seed
npm run build
npm run start:prod
```

`start:prod` 会设置 `NODE_ENV=production` 并启动 `dist/main.js`（不是 `dist/src/main.js`）。`seed` 只在首次创建员工时写入密码，再次执行不会覆盖已有密码哈希；五个初始密码必须互不相同且不等于固定邀请码。

健康检查：

```text
https://api.example.com/health
https://api.example.com/health/ready
```

生产环境上线后，请立即修改种子账号默认密码。

## 管理后台

进入管理后台目录：

```bash
cd apps/admin
cp .env.example .env.local
```

修改 `.env.local`：

```env
NEXT_PUBLIC_API_URL=https://api.example.com
NEXT_PUBLIC_BACKEND_ROLE=ADMIN
```

为**五个**后台分别设置对应的 `NEXT_PUBLIC_BACKEND_ROLE`（`ADMIN`、`MANAGER`、`FINANCE`、`BUSINESS`、`SUPPORT`），并分别构建和部署到各自域名。每个入口共享同一个 API 和数据库。

| 角色 | `NEXT_PUBLIC_BACKEND_ROLE` | 本机端口 | 示例域名 | 启动命令 |
| --- | --- | --- | --- | --- |
| 超级管理员 | `ADMIN` | `3002` | `admin.example.com` | `npm run start:admin` |
| 管理员 | `MANAGER` | `3004` | `manager.example.com` | `npm run start:manager` |
| 财务 | `FINANCE` | `3005` | `finance.example.com` | `npm run start:finance` |
| 业务员 | `BUSINESS` | `3006` | `business.example.com` | `npm run start:business` |
| 专用运营员 | `SUPPORT` | `3007` | `operator.example.com` | `npm run start:support` |

构建与启动（**每个角色必须单独 build**，因为 `NEXT_PUBLIC_*` 在构建时写入浏览器包；HTTPS 域名没有端口，不能依赖本机端口推断角色）。

推荐用仓库脚本一次性构建五个独立产物目录（`.next-ADMIN` … `.next-SUPPORT`）：

```bash
NEXT_PUBLIC_API_URL=https://api.example.com ./scripts/build-admin-roles.sh
cd apps/admin
NEXT_DIST_DIR=.next-ADMIN    npm run start:admin
NEXT_DIST_DIR=.next-MANAGER  npm run start:manager
NEXT_DIST_DIR=.next-FINANCE  npm run start:finance
NEXT_DIST_DIR=.next-BUSINESS npm run start:business
NEXT_DIST_DIR=.next-SUPPORT  npm run start:support
```

手工示例（超级管理员）：

```bash
# 示例：超级管理员
export NEXT_PUBLIC_API_URL="https://api.example.com"
export NEXT_PUBLIC_BACKEND_ROLE="ADMIN"
export NEXT_DIST_DIR=".next-ADMIN"
npm ci
npm run build
npm run start:admin
```

对 `MANAGER` / `FINANCE` / `BUSINESS` / `SUPPORT` 重复上述流程，分别部署到对应域名与端口。**不要**用同一个 `.next` 目录起五个进程。

所有 `start:*` 脚本已绑定 `0.0.0.0`，便于 Nginx 从本机反代。部署时由 Nginx 终结 HTTPS 并转发到对应端口。

### systemd 示例（单个后台角色）

```ini
[Unit]
Description=HNW Admin ADMIN
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/hnw/apps/admin
Environment=NODE_ENV=production
Environment=NEXT_DIST_DIR=.next-ADMIN
Environment=PORT=3002
ExecStart=/usr/bin/npm run start:admin
Restart=always
RestartSec=5
User=hnw

[Install]
WantedBy=multi-user.target
```

为 `MANAGER` / `FINANCE` / `BUSINESS` / `SUPPORT` 各复制一份，改 `Description`、`NEXT_DIST_DIR` 与对应 `start:*`。

财务上下分为**单人确认立即入账**，不走双人复核。超管菜单中的「余额调整复核」仅处理超级管理员发起的余额调整申请，与财务上分订单无关。

## 客户 App

客户 App 的接口地址通过 `API_BASE_URL` 注入。

Web 构建：

```powershell
cd apps/client
flutter pub get --enforce-lockfile
flutter build web --release --dart-define=API_BASE_URL=https://api.example.com
```

Android APK：

```powershell
cd apps/client
flutter pub get --enforce-lockfile
flutter build apk --release --dart-define=API_BASE_URL=https://api.example.com
```

Android AAB（应用商店）：

```powershell
flutter build appbundle --release --dart-define=API_BASE_URL=https://api.example.com
```

正式发布前必须配置 Android release 签名，详见 `docs/客户APP发布配置.md`。

## Nginx 反向代理

API 需要支持普通 HTTP 请求和 WebSocket 行情连接。反向代理时要保留升级头：

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;
    # ssl_certificate /etc/letsencrypt/live/api.example.com/fullchain.pem;
    # ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
    client_max_body_size 50m;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}
```

KYC 上传（证件双面 + 自拍 + 签名，经 Base64）接近 API 的 48 MB JSON 上限，反向代理请设置 **`client_max_body_size 50m`**。

五个运营后台按普通 Next.js 服务分别反向代理到 `3002` / `3004` / `3005` / `3006` / `3007`。

## 上线检查

上线前确认：

**环境与进程**
- `.env` 含 `NODE_ENV=production` 与全部必填密钥（见上文）
- `npm run start:prod` 可启动；`/health` 与 `/health/ready` 正常
- systemd/PM2 开机自启

**后台与 App**
- 五个角色分别用正确的 `NEXT_PUBLIC_BACKEND_ROLE` **构建**后部署
- 超级管理员、管理员、财务、业务员、专用运营员都能登录
- 客户注册只显示手机号、密码、邀请码
- KYC 只允许 Aadhaar 或 PAN；上传不被反代 413
- Deposit 进入在线客服，不在 App 内提交入金申请
- Withdraw 可以提交，并生成订单号
- 财务可以单人审核提现与创建上分订单（无需双人复核）
- 业务员只能看到自己的客户
- 专用运营员仅能看到固定邀请码客户

**安全**
- 已修改种子账号默认密码
- 数据库仅内网；HTTPS 已启用；备份任务已配置
- 未将 `.env` / keystore 提交到仓库

## 生产安全项

- 修改所有默认后台账号密码
- 使用强 `JWT_SECRET` / `TWO_FACTOR_ENCRYPTION_KEY` / `OTC_KEY_ENCRYPTION_SECRET` / `OBJECT_SIGNING_SECRET`
- 数据库只允许服务器内网访问
- 配置 HTTPS
- 设置数据库自动备份
- 不要提交 `.env`、`.env.local`、`key.properties`、keystore 文件
- 定期导出资金流水、提现记录和审核日志

## 备份

在服务器上（已安装 `pg_dump` / `pg_restore` / `tar`）。**推荐 Linux shell 脚本**：

```bash
export DATABASE_URL="postgresql://正式用户:密码@127.0.0.1:5432/正式库"
export PRIVATE_OBJECT_ROOT="/var/lib/hnw/private-objects"
chmod +x scripts/backup-postgres.sh scripts/restore-postgres.sh scripts/backup-private-objects.sh
./scripts/backup-postgres.sh "/var/backups/hnw/hnw-$(date +%Y%m%d%H%M).dump"
./scripts/backup-private-objects.sh "/var/backups/hnw/objects-$(date +%Y%m%d%H%M).tar.gz"
# 恢复 DB：./scripts/restore-postgres.sh /var/backups/hnw/某个.dump
# 恢复对象：tar -C /var/lib/hnw -xzf /var/backups/hnw/objects-….tar.gz
```

Windows 运维机可用同等 PowerShell 脚本：`scripts/backup-postgres.ps1` / `scripts/restore-postgres.ps1`。

### crontab 示例（每日 02:30）

```cron
30 2 * * * DATABASE_URL='postgresql://正式用户:密码@127.0.0.1:5432/正式库' /opt/hnw/scripts/backup-postgres.sh /var/backups/hnw/hnw-$(date +\%Y\%m\%d).dump >> /var/log/hnw-backup.log 2>&1
35 2 * * * PRIVATE_OBJECT_ROOT=/var/lib/hnw/private-objects /opt/hnw/scripts/backup-private-objects.sh /var/backups/hnw/objects-$(date +\%Y\%m\%d).tar.gz >> /var/log/hnw-backup.log 2>&1
```

保留策略由运维自行清理旧 dump / tar（例如只保留近 14 天），并建议异地拷贝。
