# HNW 小白部署与运维手册

最后更新：2026-09-30

本手册把日常操作压缩成“GitHub 验证 → Coolify 人工批准 → 自动健康检查”。不要在生产服务器直接改代码，也不要把数据库、Redis、KYC 文件目录暴露到公网。

## 一、推荐结构

- GitHub：保存代码、Pull Request 和 CI 结果。
- Coolify：可视化构建、部署、日志、回滚和域名证书。
- `compose.production.yaml`：生产应用模板，只包含 API 和五个后台；数据库与 Redis 推荐使用独立托管服务或独立私有服务。
- PostgreSQL：独立备份并定期恢复演练。
- 私有对象目录：持久加密磁盘，保存 KYC 等非公开文件，并做异地备份。

仓库不会提供真实域名、商业行情凭据、扫描服务凭据或生产密钥。它们必须在正式供应商和服务器准备好后填入 Coolify。

## 二、首次部署（只做一次）

1. 准备 Linux 服务器并安装 Coolify；开启系统自动安全更新，只开放 SSH、HTTP、HTTPS。
2. 在 Coolify 连接 GitHub 仓库，选择 `compose.production.yaml`。
3. 复制 `.env.production.example` 中的变量名到 Coolify Environment Variables，逐项替换示例值。
4. 使用独立 PostgreSQL 和 Redis 私网地址；不要在公网开放 5432 或 6379。
5. 创建 `/srv/hnw/private-objects`，挂载加密持久磁盘，并限制为应用运行用户可读写。
6. 为 API 和五个后台分别绑定域名，开启自动 HTTPS。
7. 在第一次启动应用前，使用 Coolify Terminal 运行一次迁移服务：

   ```bash
   docker compose -f compose.production.yaml --profile operations run --rm migration
   ```

8. 首次初始化账号时再执行 seed；后续发布不得重复依赖 seed 修改既有账号。
9. 部署成功后检查 API `/health/ready` 和五个后台 `/login`。
10. 立即更换首次初始化的五个后台密码。

## 三、每次发布（固定流程）

1. 在功能分支修改代码。
2. 本机运行仓库验证。
3. 创建 Pull Request；等待所有必需 CI 变绿。
4. 合并到 `main`。
5. 在 Coolify 打开新部署，核对提交号后点击 Deploy。不要启用“未经过 CI 自动直发生产”。
6. 如有数据库 migration，先创建数据库备份，再只运行一次 migration 服务。
7. 部署完成后运行：

   ```bash
   PRODUCTION_API_URL=https://api.example.com \
   PRODUCTION_ADMIN_URLS=https://admin.example.com,https://manager.example.com,https://finance.example.com,https://business.example.com,https://operator.example.com \
   node scripts/post-deploy-smoke.mjs
   ```

8. 健康检查失败时，停止继续操作，在 Coolify Deployment History 回滚到上一个成功版本；不要连续推送猜测性修复。

## 四、面板里只需关注

- API 和五个后台是否为 Running/Healthy。
- 当前部署的 Git commit 是否正确。
- CPU、内存、磁盘是否持续异常。
- API 日志是否出现大量 5xx、数据库错误、Redis错误、行情断流或 KYC 扫描失败。
- 最近一次数据库与私有对象备份是否成功。
- HTTPS 证书是否正常自动续期。

## 五、危险操作分级

### 绿色：可直接查看

状态、日志、指标、健康检查、部署历史、备份历史。

### 黄色：确认影响后执行

重启服务、重新部署同一提交、创建备份、运行只读诊断。执行前确认没有正在进行的资金或迁移操作。

### 红色：必须先备份并记录

数据库迁移、恢复数据库、恢复私有对象、回滚包含数据库结构变更的版本、删除卷、修改生产密钥。AI 首次接触生产环境只能只读检查；未经明确批准不得执行红色操作。

## 六、备份要求

- PostgreSQL：每天自动备份，至少保留 30 天，并复制到不同服务器或对象存储。
- 私有对象：每天增量备份，备份位置与应用服务器分离。
- 每月使用独立数据库和独立目录执行 `scripts/recovery-drill.ps1`，保存 JSON 报告。
- “备份任务显示成功”不等于可恢复；只有恢复演练通过才算有效。

## 七、故障处理

1. 先截图或保存日志，不要直接删除容器或数据卷。
2. 检查 `/health/live`、`/health/ready` 和 `/health/version`。
3. 如果只是新版本异常，回滚应用版本。
4. 如果涉及数据库、资金、订单或 KYC 数据，暂停写操作并联系技术人员；不要自行执行 SQL。
5. 导出提交号、时间、错误日志、受影响账号范围和已执行操作，供后续排查。

## 八、仓库已提供与外部待办

仓库已提供：生产 Compose、Docker 镜像、健康检查、配置预检、发布后冒烟、备份/恢复脚本、监控配置和 CI 门禁。

仍需外部完成：购买服务器和域名、配置 DNS、商业行情供应商、真实病毒扫描服务、正式短信/客服/告警渠道、生产数据库与 Redis、密钥生成与托管、Android/iOS 签名及真机验收。
