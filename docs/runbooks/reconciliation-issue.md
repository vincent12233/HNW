# 财务对账差异处置手册

## 影响与触发

任一只读对账项非零、重复幂等键、outbox 死信或现金/持仓冻结值与业务事实不一致时触发。对账告警视为财务完整性事件。

## 检查顺序

1. 冻结相关发布和高风险后台操作，保存发布 SHA、数据库只读快照与审计证据。
2. 在单实例互斥锁下重新执行只读对账，确认问题类型、首次出现时间和受影响记录范围。
3. 核对订单、成交、资金流水、冻结金额/数量与 outbox；检查数据库和工作者重启时间。
4. 确认是否为监控延迟、未消费 outbox 或真实账务差异，不通过猜测归因。

## 安全缓解与回滚

- 可暂停受影响操作和消费工作者，保持只读查询及证据完整。
- 应用可以回滚至上一个镜像，但不得反转已经提交的财务事实。
- 任何修复均需双人复核、显式迁移/补偿记录、幂等脚本和完整审计；普通确认按钮只确认事件，不修余额。

## 升级与禁止事项

立即通知财务负责人、安全负责人和技术负责人。资金差异不得仅由单人关闭。

禁止直接执行无审计 SQL、删除流水/订单、重建余额覆盖差异、重复执行非幂等补偿或将差异标记为已解决后不保留证据。
