# 企业级升级回滚方案

## 原则

应用和配置可以回滚，已提交的订单、成交、资金流水、KYC 审计及存款事实不能通过回滚删除或反转。数据库变更使用向前兼容的修复迁移；不得把旧数据库快照覆盖到活动账本。

## 启动条件

达到渐进发布停止条件、关键依赖恢复失败、数据完整性范围不明或负责人要求时，立即停止流量扩大并启动回滚。

## 顺序

1. 宣布事件、冻结发布，保存 SHA、镜像、配置、时间线和只读证据。
2. 必要时暂停风险写入，保持安全查询；确认正在处理的请求和 outbox 状态。
3. 将应用流量切回上一个已验证的不可变镜像，不执行破坏性数据库降级。
4. 验证健康/就绪、登录、行情、订单查询、后台权限和审计。
5. 恢复消费者并执行订单、成交、现金、持仓、冻结与 outbox 对账。
6. 只有对账差异为 0 且负责人批准后才逐步恢复流量。

## 禁止事项

禁止删除订单或流水、手调余额掩盖差异、清空 Redis/队列、复用新幂等键重复请求、跳过财务复核、直接部署浮动标签或在生产现场修改未版本化代码。
