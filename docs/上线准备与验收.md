# 上线准备与验收

本项目已有客户 App、五角色后台、交易与资金服务和自动化单元测试。代码构建成功、容器启动成功和 APK 安装成功分别证明不同事项，不能单独作为正式上线依据。

升级应保留既有业务方式：印度手机号、密码和邀请码注册；注册后 KYC；存款经在线客服和财务处理；客户在 App 申请提款；交易产品和审批规则保持原约定。界面、反馈、可靠性和测试的改进不应暗中改变这些流程。

## 1. 发布必须满足的技术门槛

- [ ] 发布提交的 API lint、单元测试和构建通过。
- [ ] 后台 lint、单元测试、TypeScript 检查和生产构建通过；五个角色使用各自的构建配置。
- [ ] Flutter 分析、测试和正式 Android 包构建通过。正式包配置实际 HTTPS API，并使用正式签名。
- [ ] 在独立 PostgreSQL 数据库中，从空库迁移和种子初始化成功；从上一生产版本升级也成功。
- [ ] 重复审批同一入金或提款只能成功一次。并发提款、下单、审批不会重复入账或超扣余额。
- [ ] 事务中注入失败后，申请状态、余额、冻结金额、账户流水和操作审计一致回滚。
- [ ] 五角色权限矩阵实测通过，包含跨客户、跨角色、直接 API 请求的越权拒绝。
- [ ] 登录失效、密码变更和注销后的令牌行为符合明确的会话策略。
- [ ] 对发布提交执行浏览器和 Android 业务 E2E，并保存结果、日志、设备信息和提交号。

API CI 已启动 PostgreSQL 和 Redis，验证空库迁移、带账户流水数据的最新迁移升级、数据库约束与部分并发测试；完整业务链路的真实数据库并发验收仍须独立补齐。

当前 access token 有效期为 24 小时，refresh token 为 30 天；注销通过递增 `authVersion` 撤销该账户的所有现有令牌，不支持只撤销单台设备。正式发布前仍应核验账户禁用、密码变更和多设备会话边界。

## 2. UI / UX 验收

### 后台

- [ ] 320、390、768、1440 像素宽度，以及较短窗口高度下，菜单末项和退出入口均可访问。
- [ ] 桌面侧栏和手机抽屉独立滚动，手机抽屉可关闭，菜单文字与背景保持可读。
- [ ] 五角色只出现可访问入口；带筛选参数的页面、前进和后退保持正确选中状态。
- [ ] 登录支持键盘、密码管理器和屏幕阅读器；请求中防止重复提交。
- [ ] 断网、超时和服务器故障有明确提示及重试入口；失败的财务或风险数据不能显示为正常的零值。
- [ ] 表格窄屏滚动、长金额、长姓名、空结果、分页和搜索均可用。
- [ ] 高风险操作的对象、金额、结果清楚可见；失败时不会误报成功。

### 客户 App

- [ ] 小屏、大字号和系统键盘弹出时，表单与主要按钮可达。
- [ ] 行情开闭市状态以服务端结果显示，行情连接异常有延迟提示，未知状态不伪装成正常。
- [ ] 风险披露可从账户页和帮助入口打开；刷新和离线备用文档提示可见。
- [ ] 加载、空列表、断网重连和返回操作保留合理状态。
- [ ] 注册、KYC、存款联系客服、提款、交易以及历史记录完整走通。
- [ ] App 从后台恢复、网络切换和重启后，会话及页面数据正确恢复。

## 3. Android 测试范围

`scripts/build-android-e2e.ps1` 是测试环境准备脚本：检查 API/数据库、选定设备、构建 APK、建立 ADB 映射、安装并启动。它不包含页面操作断言。

```powershell
# 默认本机 API 3100，只有一台已授权设备时
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-android-e2e.ps1

# 多设备时必须明确选择
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-android-e2e.ps1 -DeviceSerial YOUR_DEVICE_SERIAL

# 无需手机的脚本故障回归
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\tests\android-e2e.test.ps1
```

真机验收至少包括：

1. 新测试客户按既有流程注册、提交 KYC、后台审核、登录。
2. 联系客服存款，财务审核后核对 App 余额和流水。
3. 使用测试行情下单，核对持仓、订单、成交和不同角色后台记录。
4. 提交提款，核对冻结、审核、余额变化和拒绝后资金释放。
5. 打开 Risk Disclosure，核对后台发布内容与客户端展示。
6. 在断网、超时、重复点击、切后台恢复情况下重复关键步骤。

只使用合成身份资料和隔离测试资金。上述结果不能替代外部支付、行情授权、交易执行或清算对接的实际验收。

## 4. 生产环境与恢复

- [ ] 正式域名、HTTPS、CORS 白名单和各后台构建角色已验证。
- [ ] 所有生产密钥和初始密码单独配置，不使用本机 Compose 的测试值。
- [ ] 数据库与 KYC 私有文件持久化、访问隔离，病毒扫描服务可用。
- [ ] `/health/live` 用于进程存活，`/health/ready` 用于数据库就绪；故障时告警触发。
- [ ] 数据库与私有文件均有定时备份，完成一次实际恢复演练，记录恢复耗时和数据时间点。
- [ ] 监控 API 错误率、请求延迟、数据库容量、资金对账异常、行情新鲜度及备份失败。
- [ ] 汇集结构化日志中的 `requestId`、`statusCode`、`durationMs`，按 `auth_login_rejected`、`auth_refresh_rejected`、`order_submit_rejected`、`withdrawal_request_rejected`、`kyc_submit_rejected` 和 `rate_limit_blocked` 建立告警阈值。事件仅表示接口拒绝，不等同于已确认的密码错误、交易失败或 KYC 文件扫描失败；不得记录密码、令牌及上传内容。
- [ ] 发布记录包含应用版本、Git 提交号、迁移版本、配置变更和回退步骤。
- [ ] 确认 `compose.local-test.yaml` 只绑定本机端口，不直接用于正式公网部署。

## 5. 运营资料与服务内容

风险披露入口和文档模板仅是产品功能。仓库默认条款仍包含“上线前由运营主体补齐”的文字，应由运营主体确认真实信息后发布：

- [ ] 法律实体名称、地址、客服与投诉升级渠道。
- [ ] 实际具备的许可或登记信息及对应服务范围。
- [ ] 最终隐私政策、服务条款、风险披露的版本、生效时间和语言。
- [ ] 行情使用权限、数据延迟说明、客服配置及正式服务响应安排。
- [ ] 应用商店资料、隐私声明、签名管理和版本回退安排。

## 6. 验收证据

每次发布保留：提交号、命令、退出码、测试报告、浏览器/设备/系统版本、截图或操作记录，以及未通过项的负责人。明确标注“通过”“失败”“未执行”，不要用上一提交的结果覆盖本次未执行项目。

当前工具链提供代码测试和局部脚本回归；浏览器视觉验收、真实 PostgreSQL 并发检查和完整 Android E2E 仍需逐项取得证据后，才能作出上线决定。
