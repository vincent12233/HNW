# 订单状态未知处置手册

## 影响与触发

适用于下单超时、客户端显示“正在确认”、订单 SLO 告警或用户无法确认订单结果。目标是确认已有事实，不重复创建订单。

## 检查顺序

1. 记录告警时间、环境、发布 SHA 和匿名请求关联号；不得把手机号、账户号或金额贴入公共频道。
2. 查询原 `clientOrderId` 对应订单和审计记录，确认 API、数据库、撮合工作者和 outbox 状态。
3. 检查 Redis、PostgreSQL、撮合租约、队列积压和最近部署；核对只读对账结果。
4. 通过订单查询接口确认最终状态。网络超时不代表下单失败。

## 安全缓解与回滚

- 暂停新发布；异常扩大时关闭订单入口或缩小流量，但保留查询能力。
- 仅使用相同幂等键安全重试查询/提交；禁止生成新键替代未知请求。
- 应用回滚不得回滚数据库中的已成交、已冻结或资金流水事实。
- 恢复后运行订单、成交、冻结资产和 outbox 对账，结果必须为零差异。

## 升级与禁止事项

立即通知交易平台、财务平台和值班负责人。出现资金差异、重复订单或范围不明时升级为最高级事件。

禁止直接修改订单状态、删除成交/流水、手工调整余额、清空队列或让用户盲目重复下单。
