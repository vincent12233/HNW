# 生产部署说明

这份说明用于把当前项目部署到正式服务器。正式环境至少需要一台后端服务器、一个 PostgreSQL 数据库、五个可访问域名，以及客户 App 的正式 API 地址。

## 推荐域名

| 用途 | 示例 |
| --- | --- |
| API 后端 | `https://api.example.com` |
| 超级管理员后台 | `https://admin.example.com` |
| 管理员后台 | `https://manager.example.com` |
| 财务后台 | `https://finance.example.com` |
| 业务员后台 | `https://business.example.com` |
| 专用运营员后台 | `https://operator.example.com` |
| 客户 Web App，可选 | `https://app.example.com` |

如果只发布 Android App，客户 Web App 域名可以不配置。

## 服务器环境

推荐准备：

- Node.js **24** 推荐（CI / Docker）；运行 Nest 12 API 最低 **20.19+** 或 **22.12+**（勿用 21.x）。本地跑 API 单测建议 Node **24.9+**（Jest `require(esm)`）
- API 使用 **ESLint 10**（`npm run lint`）；类型感知规则与 Prettier 目前以 warning 为主，CI 会跑 lint
- npm
- PostgreSQL 17 或更高版本（与本地 compose 一致；最低可用 15+）
- Flutter SDK 3.47.4（stable，与 CI / 客户 Web Docker 镜像一致），用于客户 App 打包
- Java JDK，用于 Android APK/AAB 打包
- Nginx 或同类反向代理
- HTTPS 证书

## API 后端

进入 API 目录：

```powershell
cd apps/api
Copy-Item .env.example .env
```

修改 `.env`：

```env
DATABASE_URL="postgresql://正式数据库用户:正式数据库密码@数据库地址:5432/正式数据库名?schema=public"
SHADOW_DATABASE_URL="postgresql://正式数据库用户:正式数据库密码@数据库地址:5432/正式影子数据库名?schema=public"
JWT_SECRET="换成高强度随机密钥"
CORS_ORIGINS="https://admin.example.com,https://manager.example.com,https://finance.example.com,https://business.example.com,https://operator.example.com,https://app.example.com"
PORT=3000
MATCHING_MAX_FILL_QUANTITY=1000
UPSTOX_ACCESS_TOKEN=
```

安装依赖、迁移数据库、构建并启动：

```powershell
npm install
npm run db:migrate
npm run db:generate
npm run seed
npm run build
npm run start:prod
```

健康检查地址：

```text
https://api.example.com/health
```

生产环境上线后，请立即修改种子账号默认密码。

## 管理后台

进入管理后台目录：

```powershell
cd apps/admin
Copy-Item .env.example .env.local
```

修改 `.env.local`：

```env
NEXT_PUBLIC_API_URL=https://api.example.com
NEXT_PUBLIC_BACKEND_ROLE=ADMIN
```

为**五个**后台分别设置对应的 `NEXT_PUBLIC_BACKEND_ROLE`（`ADMIN`、`MANAGER`、`FINANCE`、`BUSINESS`、`SUPPORT`），并分别构建和部署到各自域名。每个入口共享同一个 API 和数据库。

| 角色 | `NEXT_PUBLIC_BACKEND_ROLE` | 建议本地端口 | 示例域名 |
| --- | --- | --- | --- |
| 超级管理员 | `ADMIN` | `3002` | `admin.example.com` |
| 管理员 | `MANAGER` | `3004` | `manager.example.com` |
| 财务 | `FINANCE` | `3005` | `finance.example.com` |
| 业务员 | `BUSINESS` | `3006` | `business.example.com` |
| 专用运营员 | `SUPPORT` | `3007` | `operator.example.com` |

构建：

```powershell
npm install
npm run build
npm run start
# 或按角色：npm run start:admin / start:manager / start:finance / start:business / start:support
```

默认本地服务端口由 Next.js 控制，部署时建议由 Nginx 反向代理到后台服务。

财务上下分为**单人确认立即入账**，不走双人复核。超管菜单中的「余额调整复核」仅处理超级管理员发起的余额调整申请，与财务上分订单无关。

## 客户 App

客户 App 的接口地址通过 `API_BASE_URL` 注入。

Web 构建：

```powershell
cd apps/client
flutter pub get
flutter build web --dart-define=API_BASE_URL=https://api.example.com
```

Android APK：

```powershell
cd apps/client
flutter pub get
flutter build apk --release --dart-define=API_BASE_URL=https://api.example.com
```

Android AAB，适合提交应用商店：

```powershell
flutter build appbundle --release --dart-define=API_BASE_URL=https://api.example.com
```

正式发布前必须配置 Android release 签名，详见 `docs/客户APP发布配置.md`。

## Nginx 反向代理

API 需要支持普通 HTTP 请求和 WebSocket 行情连接。反向代理时要保留升级头：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

五个运营后台可以按普通 Next.js 服务分别反向代理。

## 上线检查

上线前执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-all.ps1
```

并手动确认：

- API `/health` 正常
- 超级管理员、管理员、财务、业务员、专用运营员都能登录
- 客户注册只显示手机号、密码、邀请码
- KYC 只允许 Aadhaar 或 PAN
- Deposit 进入在线客服，不在 App 内提交入金申请
- Withdraw 可以提交，并生成订单号
- 财务可以单人审核提现与创建上分订单（无需双人复核）
- 业务员只能看到自己的客户
- 专用运营员仅能看到固定邀请码客户
- 客服标签只在 SaleSmartly 工作台展示

## 生产安全项

- 修改所有默认后台账号密码
- 使用强 `JWT_SECRET`
- 数据库只允许服务器内网访问
- 配置 HTTPS
- 设置数据库自动备份
- 不要提交 `.env`、`.env.local`、`key.properties`、keystore 文件
- 定期导出资金流水、提现记录和审核日志
